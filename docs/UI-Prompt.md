# Pencil UI 设计提示词

适用产品：个人待办与长期目标管理应用 Daily & Beyond。依据：个人待办与长期目标 PRD v1.1。日期：2026年9月28日。

本文包含一个可以直接使用的首轮提示词，以及四轮续写提示词。提示词面向 Pencil / pen.dev 的设计画布，不依赖某个固定版本的工具调用名称。此文件是设计指令，不是已经生成的 UI 稿。

## 2026-10-09 专注计时与今日时间显示修订（优先于历史轮次）

本轮的设计与实现都已落地（应用侧对应 `.github/story/story.md`，代码在 2026-10-10 的提交里）。下文历史轮次中关于今日列表时间文字、任务详情底部按钮区的表述以本节为准。**画布还没有跟上本节第 8 节之后的几次修订**，要动的画板逐条列在第 9 节。

**命名说明。** 本节中的 `Focus` 指「专注计时」，与组件库中已有的 `Button / Focus`、`Input / Focus`（键盘焦点态）无关，不要把两者合并或复用。

### 1. 今日筛选下的时间文字（D01 / M01）

筛选选中「今日」时，日期已知是今天，行内时间文字只显示时刻，不重复日期。同一任务的完整时间在任务详情页照常显示日期。

| 时间取值 | 今日筛选下的显示 | 其他筛选下的显示 |
| --- | --- | --- |
| 起止都是时刻，且都在今天 | `08:00–09:00` | `08:00–09:00` |
| 只有开始时刻，在今天 | `08:00` | `08:00` |
| 只有结束时刻，在今天 | `18:00 前` | `18:00 前` |
| 取值是某一天（今天） | 不显示时间文字 | `10月8日` |
| 时刻不在今天，如 10月20日 09:30 | `10月20日 09:30` | `10月20日 09:30` |
| 逾期项（昨天 17:00） | `10月7日 17:00` | `10月7日 17:00` |

规则是「只省略今天这个日期，不省略任何仍有信息量的日期」。重复行动行本来就只显示时刻，保持原样。

### 2. 新增基础组件（00 Foundations / 组件库）

- **`Focus / Bar`（计时条，跨页面可见）**
  - 高 56，圆角 12，左右内边距 16，底色 `MovoColor.tint`（#247367 的浅色）；左侧主文案 15pt 字重 500，上行是任务标题（单行截断），下行 12pt `MovoColor.muted`。
  - 进行中：下行「剩余 18:23 · 到 15:00」；右侧为「暂停」图标按钮（28×28）与「结束」文字按钮。
  - 已暂停：底色改为 `MovoColor.soft`（#EEF2ED），下行「已暂停 · 剩余 18:23」，右侧「暂停」变为「继续」。
  - 倒计时归零后：白底加 `MovoColor.warning`（#A96A22）1pt 边框，下行「已超出 03:12」，右侧为「结束」。这是计时中的显示变体，不是独立状态。
  - 正计时（无终点）：下行「已专注 12:40」。
- **`Focus / Dial`（计时盘，iPhone 主视觉）**
  - 直径 220，环线宽 10，圆头端点，从 12 点方向顺时针。
  - 倒计时：底环 `MovoColor.soft`，进度环 `MovoColor.primary`，**环长表示剩余比例**，随剩余减少而退去。
  - 正计时：不画进度环，改为外圈 60 段刻度点，已过的段染 `MovoColor.primary`。
  - 已暂停：进度环与刻度点整体改为 `MovoColor.muted`，盘中心追加暂停图标。
  - 倒计时归零后：环走到满且改为 `MovoColor.warning`，刻度点同理。
  - 盘内：主数字 56pt 字重 500、等宽数字；下方副行 14pt `MovoColor.muted`，与主数字间距 10。
- **`Focus / StepChips`（时长快捷取值）**：一行 chips `15 / 25 / 30 / 45 / 60`，单选，选中态用 `MovoColor.primary` 描边加浅底；用于补记浮层。
- **`Focus / DiffTag`（计划与实际差异）**：12pt 标签，超出计划用 `MovoColor.warning`（#A96A22），少于计划用 `MovoColor.muted`，文案形如「比计划多 10 分钟」「比计划少 5 分钟」「与计划一致」。**本轮没有界面落点**——它原本只出现在「保存这次投入」浮层里，而那一层已经取消（见第 8 节）。`FocusPolicy.diffTag` 保留在领域层并有用例，将来补「改这次投入」时可以直接用。

### 3. 新增画板：Mac 专注计时（1440×960）

Mac 与 iPhone 共用同一个计时页（`Route.focus` / `FocusSessionScreen`），差别只在返回方式；`Focus / Bar` 是**额外**挂在详情列顶部的一条，用来在切到别的页面时也看得见剩余时间，不替代计时页。第 8 节记了这次修订的来由。

1. **`D14-Focus Mac 专注计时`（计时中）。** 独立的计时页，与 `M15-Focus` 同构：标题、`Focus / Dial`、主按钮「暂停」、文字按钮行「结束」「放弃」。按下「开始专注」直接进到这一页，不是「在详情页顶部插一条计时条」。
2. **`D14-Focus-Paused Mac 专注计时暂停`。** 同一页的暂停态：盘与刻度点变灰，主数字冻结，主按钮「继续」。暂停中不给「暂停」，那一刻它已经暂停了，按下去不会有任何反应。
3. **计时中的任务详情页**（`D07-Default` 的计时变体，画板名待定）。从计时页返回后的样子：内容区顶部是 `Focus / Bar`（倒计时中，下行「剩余 18:23 · 到 15:00」），标题下方的主操作区把「开始专注」换成「暂停」（主，整行、高 52），下方一排次按钮为「结束专注」+「记录一次行动」；「开始专注」在此状态不再出现。

### 4. 新增画板：iPhone 专注计时（393×852）

计时页是一个可以下拉收起的页面，收起后回到进入前的任务上下文。顶部为 36×5 的圆角收起胶囊，居中，距顶 12。

**用户可见的计时状态只有三个：未开始、计时中、已暂停。** 下面的 `CountUp`、`Overrun` 是「计时中」的显示变体，都不要在界面上再引入额外的状态名或状态标签。

1. **`M15-Focus iPhone 专注计时`（倒计时中）。** 收起胶囊；任务标题 16pt 字重 500 居中（如「准备季度汇报」）；中部 `Focus / Dial` 显示剩余 `18:23`，副行「到 15:00 结束」；底部左右边距 24、高 52 的主按钮「暂停」；再下一行居中的两个文字按钮「结束」「放弃」，`MovoColor.muted`，中点分隔。
  标题下面不再有 12pt 计划标签，盘下也不再有常驻提示。这一页处在「正在做」的状态里，标题与主按钮之间只应该隔着那个数字；规则性的句子（暂停不计入投入、结束与放弃的区别）每次进来都一模一样，写在这里只是让人多读一遍。
2. **`M15-Focus-CountUp iPhone 正计时`。** 任务没有起止时间也没有预计投入时，`Focus / Dial` 用刻度点样式，主数字为已用 `12:40`，副行「已专注」。其余同上。`FocusPolicy.planLabel` 对这种情况算出来的「未设置时长，正计时」不显示在这一页上：主按钮已经写着「开始专注 · 正计时」。
3. **`M15-Focus-Paused iPhone 专注暂停`。** 环与刻度点整体变灰，主数字冻结为暂停时刻的值，副行「已暂停 · 已暂停 02:14」；盘下提示「继续后从 18:23 接着走」；主按钮「继续」，文字按钮行不变。暂停是常态里唯一在盘下留一句话的，因为「继续之后从哪接着走」看数字看不出来。
4. **`M15-Focus-Overrun iPhone 倒计时归零后`。** 环满且变警告色，主数字为超出时长 `+03:12`，副行「已超过计划时间」；盘下提示「到点后仍在计时，不会自动结束。」；主按钮「结束」，文字按钮行为「暂停」「放弃」。界面不出现「到点未响应」之类的状态标签，超时只体现为数字前缀与配色变化。这句留着同样是上面那个理由：不说，用户会坐在那儿等它自己停。
5. **`M15-Focus-Collapsed iPhone 收起后的计时条`。** 在 `M01 iPhone 待办` 顶部安全区下方插入 `Focus / Bar`，证明收起后切换到其他页面仍能看到剩余时间；页面其余部分与 M01 一致。

### 5. 新增画板：补记浮层

**记录一次行动（补齐）。** 新增 `D14-Log Mac 记录一次行动`（560 宽）与 `M15-Log iPhone 记录一次行动`。用于不启动计时而直接补记。内容：

- 标题「记录一次行动」。
- 投入时长：数字输入配 `Focus / StepChips`，默认为空。
- 说明输入「补一句说明（可选）」。
- 发生时间：复用 `TimeField`，默认「现在」，可改为某一天或某一时刻。
- 脚注「记录投入不等于任务完成；要标记完成请单独操作。」
- 主按钮「保存记录」。

### 6. 改动已有画板

- **`D07-Default Mac 任务详情 · 正常范围` 与 `M12-Default iPhone 任务详情 · 正常范围`。** 主操作区改为紧跟任务标题块之后，不再挂在整页滚动的末尾——原先要滚过所属与时间、子任务、步骤、行动记录、变更历史才看得到一个 44 高的按钮，而且它和旁边两个次按钮一样大。内容与规格：
  - 主按钮「开始专注」，整行撑满、高 52、圆角 12、`$primary` 底 + `$on-primary` 字，图标 `play.fill`。副文案显示推导出的时长，如「开始专注 · 30 分钟」；没有起止时间也没有预计投入时显示「开始专注 · 正计时」。计时中改为「暂停」（`pause.fill`），暂停中改为「继续专注」（`play.fill`）。
  - 主按钮下方一排次按钮：计时中与暂停中都是「结束专注」；`children` 为空时加「标记完成 / 重新打开」；然后是「记录一次行动」。窄屏或大字号放不下时改为竖排。
  - 计时中主按钮给「暂停」而不是「结束专注」：结束不再经过确认框，按一下就直接写进一条记录，所以最显眼的那个位置留给能退回来的动作。这也回到「主操作 / 次要操作」那张表（计时中＝暂停 / 结束；已暂停＝继续 / 结束）。
  - 主操作区整体限宽 420 并左对齐。详情页内容列是 760，主按钮若铺满整列就成了一条横穿页面的长条，不再像一个按钮；420 与浮层、空状态等其它「单件内容」同宽。
  - 原本点击任务进入详情的路径不变，计时是详情页内的独立入口，不改变任何行或卡片的点击行为。
  - 详情页的「…」菜单里不再放「开始专注」：同一个页面上给同一个动作两个入口只会让人犹豫该点哪个。`D01` / `M01` 清单行菜单里的那一项是另一个页面的事，保留。
  - 「行动记录」每行末尾加一个「改」文字按钮，打开「改这次投入」浮层：可改投入时长与说明，改完写一条更正记录指向原记录，旧版本仍留在库里。列表只显示当前值，所以改完是一行而不是两行——规则见第 8 节。
- **`D01 Mac 待办` 与 `M01 iPhone 待办`。** 今日筛选下：
  - 每一行末尾的「…」菜单里增加一项「开始专注」，位于「设置日期、优先级等」之后。
  - 该任务正在计时时，行尾的「…」左侧增加一个计时徽标，形如「⏱ 18:23」，点击回到计时页；不改变行本体的点击行为，行本体仍然进入任务详情。
  - 任务的筛选、分组、排序不变。
- **新增字段「预计投入」（D01-Inline / M01-Inline / D01-Inline-Edit / M01-Inline-Edit / D07 / M12）。**
  「预计投入」是「开始专注」推导倒计时长度的最后一个来源，所以它必须能在界面上设置。三个入口都要有，措辞一致：
  - 新建待办与清单就地编辑：放在「开始时间 / 结束时间」两行之后、优先级之前，一行数字输入，未设置显示「未设置」。
  - 任务详情「所属与时间」分区：原来只在时间旁只读展示，改为可编辑，并入「时间、优先级、预计投入」浮层；未设置时该行保留，不隐藏——藏起来会让用户找不到决定倒计时长度的入口。
  - 取值规则：正整数分钟，空串表示未设置。非法输入单独提示「请填整数分钟，例如 30。」，不静默当成未设置写进去。
  - 本轮的 `D01-Inline-Edit` / `M01-Inline-Edit` 与 `D07-Default` / `M12-Default` 以「汇总区域差异」为例，该任务带 30 分钟预计投入。

### 7. 画板外标注（业务口径与边界）

- 用户可见的计时状态只有未开始、计时中、已暂停三个。倒计时归零属于「计时中」的显示变体，界面上不出现额外状态标签。
- 暂停不计入投入时长。会话保存开始时刻、倒计时终点锚点与暂停区间，界面显示的剩余与已用时长都由这些字段与当前时刻推导，不依赖逐秒累加。
- 倒计时归零后只提醒一次，计时继续走并转为警告色；不自动结束计时，也不自动标记任务完成。
- 点「结束」**直接写入，不再弹确认浮层**。投入时长已经由规则算好（倒计时取计划时长、正计时取有效已用时长），再让用户确认一遍只是让他复述系统刚算出来的那个数。原先这一层同时承担「结束」与「放弃」的分流，现在分流靠计时页上的两个动作本身。
- 到点后拖延超过宽限的按锚点截断，此时结束会额外显示一条信息条「已按计划时长记下」——记下的数不等于实际坐了多久，撤掉确认浮层之后只剩这里还能说一句。
- 「结束」写入一条行动记录；「放弃」不写记录，用于误触。两个动作在界面上用文字写明差异，不只靠图标或颜色区分：**「结束」与「放弃」是两个文字按钮**，不缩成图标。
  第 8 节按反馈去掉了它们下面那句解释文案，因此「放弃会丢数据」这件事现在只由这个词承担。要补回安全网的话，更合适的做法是给「放弃」加一次确认，而不是把说明句重新堆回计时页。
- 记录投入与标记完成是两条独立写入，界面不提供「一步完成」的合并按钮。
- 到点提醒按有效剩余时间判断，暂停时撤销已排期的提醒，继续时按新的有效终点重新排期。
- 暂停中、或倒计时归零后长时间无人操作，下次打开应用提示处理，不静默作废也不静默续上。
- 独立待办（未挂计划）同样可以开始专注与记录投入。
- 锁屏与灵动岛 Live Activity、专注时长统计、跨设备同步专注会话不在本轮范围。

### 8. 实现后的修订（位置、版心与结束流程）

前七节写的是要画什么；这一节是几处实现后的修订，覆盖前文对同一元素的表述。

- **专注计时页（`D14` / `M15`）改为双向居中，版心 520。** 此前它复用了清单页的容器（限宽 760 + 左对齐）：一屏里只有标题、盘和一排按钮，沿用列表的规则之后整套东西缩到左上角，右边和下面各空一大片。左对齐是给长列表的，计时页不是列表。两个容器的差别只有「限多宽、往哪对齐」这一条，因此在 `Movo/Features/Shared/Scaffold.swift` 里并存 `ScreenScroll` 与 `FocusStage`，没有合并。
  - 小屏叠加大字号时内容会比一屏高，此时仍可滚动，只是居中的余量变成 0——不能把主按钮顶出可视区。
  - iPhone 的收起胶囊固定在屏幕顶边，不跟着内容居中：它是一个「往下拖可以收起」的把手，掉到画面中间就不再像把手。
  - 「未开始」与「计时中」共用同一个标题块，按下「开始」时页面上半部分不跳。
  - 520 与主操作区的 420 都是「单件内容的宽度」。再宽，主按钮就成了一条横穿屏幕的长条，按钮也就不再像一个按钮。
- **任务详情页的主操作区上移到标题下方。** 内容与规格见第 6 节 `D07-Default` / `M12-Default`。
- **「结束」不再弹「这次投入」确认浮层**（覆盖第 3、4、5、7 节里与此相关的表述）。`D14-Focus-Save` 与 `M15-Focus-Save` 两块画板因此取消，`Focus / DiffTag` 暂时没有落点。连带的两条：
  - 计时中的主按钮从「结束专注」换成「暂停」。结束不再有确认这一步，按一下就直接写进记录；把最显眼的位置留给能退回来的动作，才是安全的排法。这条同时让详情页回到「主操作 / 次要操作」那张表。
  - 被截断时补一条信息条「已按计划时长记下」（复用开始被拦下时的同一处横幅，只是标题跟着内容走）。记下的数不等于实际坐了多久这件事，原来只有确认浮层里那句「可以改成实际时长」在讲；撤掉它之后必须换个地方说。
- **更正过的记录只显示当前值。** 更正保留旧版本（PRD 3.4），所以库里新旧两条并存；任务详情的「行动记录」与计划详情的记录列表都按「被别的记录指向过的不再出现」过滤。导出里一直是这么做的，这轮把同一段过滤收拢到 `CorrectionHistory.current(_:)` 一处（行动记录与测量共用）。规则的一个连带性质：连改两次 A → B → C，B 也被 C 指过，结果只剩 C。
  - 更正浮层里不出现「发生时间」。「哪一天算这条记录」与「这次投入多久」不是同一个问题，改时长时顺手把日期改掉是另一种失误。
  - 撤掉确认浮层之后，「给刚结束的那次投入补一句说明」只剩「改」这一个入口：「记录一次行动」会新写一条，不是补在同一条上。
- **「开始专注」按下去就进计时页**（Mac 与 iPhone 一致）。此前三处入口——任务详情的主按钮、清单行「…」菜单里的那一项、今日清单行尾的开始入口——都只写一条会话就停住；用户看到的是页面顶上多出一条计时条，还得再点那条才进得去计时页，「我按下那一下到底生效了吗」反而成了要自己找答案的问题。现在三处都写成「开始成功 → 进计时页」；被拦下时（另一次正在计时）留在原地，让紧跟着的横幅说明原因。计时页自己那个「开始专注」不需要跳，它本来就在那一页上。
- **计时页去掉三处说明文案**（覆盖第 3、4、7 节里与此相关的表述）。这一页处在「正在做」的状态里，多出来的句子只会把视线从数字上拉走：
  - 标题下不再有 12pt 计划标签（「未设置时长，正计时」）。它在「未开始」已经写在主按钮上（「开始专注 · 30 分钟」），在计时中又和盘上的数字说同一件事。`FocusPolicy.Snapshot.planLabel` 因此暂时没有界面落点，仍保留在领域层并有用例。
  - 盘下不再有常驻提示「暂停期间不计入投入」。它写的是规则，不是此刻的信息。留下两处与状态相关的：暂停的「继续后从 18:23 接着走」，以及到点后仍在超出的「到点后仍在计时，不会自动结束。」——这两句说的都是看数字看不出来的事，后一句不说，用户会坐在那儿等它自己停。
  - 文字按钮下面不再有「「结束」会记下这次投入；「放弃」不写记录，用于误触。」这一条推翻了第 7 节「两个动作在界面上用文字写明差异」的旧写法：差异现在由「结束」「放弃」这两个词本身承担（它们仍是文字按钮，不是图标）。代价是「放弃会丢掉这次的投入」这句提醒不再出现——要补安全网的话，正确做法是给「放弃」加一次确认，而不是把说明句重新堆回这一页。
  - 「未开始」那一页同时去掉「暂停期间不计入投入。结束与标记完成是两件事。」这条通用规则，只留一句与本次任务相关的（这次会倒计时还是正计时、到点会不会自己停）。

## 2026-10-06 图表可视化修订（优先于历史轮次）

### 1. 业务口径与设计原则（画板外标注）

- **非压力化**：不设计连续打卡天数（Streak）、连续达成周数或压力型图例。所有图表只忠实陈述实际发生的事实与测量。
- **真实留白**：指标趋势缺测不补 0；回顾中无记录的日期柱高为 0 并留白；全周无记录直接展示标准空态，不绘制空白坐标轴。
- **持续型不设总百分比**：持续型计划（如「保持阅读」）只展示周期频次文字或点阵，坚决不显示总体百分比条或 100% 环。
- **语义分离**：行动记录条数、任务叶子勾选、测量结果各用独立的图表模块展示，不相互混淆。

### 产品与用户

这是面向普通个人用户的 AI 待办与长期目标管理应用，服务工作、学习、健康和生活。用户可以说一句话或输入文字，由系统建立或更新事项，自动整理到相关计划，然后持续执行、记录与回顾。

从健康计划进入“记录体重”，字段为数值68.7、单位公斤、日期9月28日、可选备注。保存按钮使用“保存记录”。结果记录没有任务完成复选框；单位不明时让用户选单位，不能自行猜测。可从历史记录进入更正状态，明确保存修改后仍可回看记录来源。

### 必须体现的约束

一次性任务、重复模板、当次实例和实际记录的操作入口要有区别；主界面仍然用普通人能理解的词。计划阶段可选，创建时不展开所有字段。iPhone 上能够独立修改计划、重复频率、阶段和记录，无需提示“请前往桌面端”。

本轮完成后，检查“创建计划 → 添加行动 → 设置频率 → 记录结果 → 暂停恢复”在手机上是否都有对应页面和明确去向。

## P3 长期执行树与回顾

请沿用当前文件，为用户持续数月的计划设计可追溯的历史。使用统一示例数据中的时间线、快照和上一周记录，避免各页面出现不同的完成数或日期。

### 新增画板

D08 Mac 周回顾
标题“回顾”，当前范围9月21日至27日。按工作、学习、健康和生活展示简短事实与记录入口。可列出工作1次记录、英语3次、散步2次、阅读2次；摘要使用“记录了什么”，不以时长给用户排名。
把确定事实、用户补记和建议分开。每条总结可点击查看来源任务或记录。健康内容为本地记录区，云 AI 建议只使用已允许的其他计划。没有原因记录时显示“未记录原因”，不自动编造解释。

D09 Mac 计划历史与阶段快照
从季度工作汇报切到“记录”。使用按日期排列的时间线，显示8月建立计划、9月阶段完成、取消封面、截止调整和行动记录。支持筛选完成、调整、记录。选中一条事件后在右侧展示发生时间、旧值、新值及用户原始说明。
新增历史快照变体 D09-Snapshot：打开9月14日的阶段快照，明确“查看9月14日记录，只读”。当时整体2/7完成、截止9月30日；提供返回当前计划，当前状态仍为3/7、截止10月9日。历史截图不展示当前编辑按钮。

M10 iPhone 周回顾
采用单列内容与可折叠分类。展示同一周的数据，点击事实可查看来源，用户可用语音补记。建议有独立采纳按钮，未采纳不出现在今日待办中。用户可以隐藏统计，只看自己关注的计划。

M11 iPhone 工作计划树
展示季度汇报的3个阶段，展开“形成初稿 → 整理分析 → 汇总区域差异”。保持清晰的缩进与路径；小屏幕按层展开，避免横向拖动大画布。点击任务进入详情，点击阶段进入阶段记录。已取消事项可通过过滤查看，不当作已完成。
增加 M11-History 与 M11-Snapshot 两个变体，保证手机可查看同样的历史和快照。持续型计划的重复行动按模板与周期折叠；补充一个阅读历史折叠例子，展开后才显示每次记录。

### 执行树的视觉规则

主要视图是可以阅读和折叠的层级列表。包含关系用缩进与轻连接线表达，前置依赖只在打开高级选项时显示。日期显示为节点属性或历史事件，不用“9月28日”作为计划树根节点。

历史上已取消、重新打开和移动的任务仍然能找到；这些状态用图标加文字区分。阶段和任务分组不能重复计入总任务数。完成、跳过、暂停分别展示，不能通过颜色统一成“成功”。

完成后沿着“今日任务 → 所属计划 → 阶段 → 行动记录 → 历史调整 → 当时快照”检查页面去向；每一步都应有足够上下文返回。

## P4 必要状态与设计收尾

请继续当前文件，补齐使用过程中必须面对的页面与状态，保持既有设计，不重新更换配色或导航。

### 新增画板

D10 Mac 搜索
搜索范围包括任务、计划、行动记录和成果标题。输入“汇报”后按类型分组结果，显示计划路径与时间，支持近期与全部。无结果时保留查询、清除按钮和“新建待办”入口。给 iPhone 提供对应的搜索浮层变体 M06-Search。

M12 iPhone 任务详情
与 D07 使用同一任务数据，改为独立详情页。重要字段在首屏，开始时间与结束时间分别编辑。记录、成果与变更历史可以展开；从今日或计划进入时能够返回原入口。

M13 iPhone 设置与计划隐私
设置包括账号、同步、AI 与数据、通知、导出。重点展示健康计划的“云端 AI 处理”和“云同步”是两个独立开关。提供仅导出当前计划的预览，健康记录默认未勾选。更多菜单中的暂停、归档和删除有不同含义，删除确认说明可恢复期，不把永久删除作为默认操作。
Mac 用对应设置面板变体 D01-Settings 实现同样的控制，不需要新造一套导航。

M14 iPhone 首次使用与空状态
首次进入直接展示简短欢迎、输入框、录音和“试着记一件事”，提供工作、学习、健康、生活四种小型示例。允许先记一条买菜待办；不要求先注册计划、选择职业、设置体重目标或开启全部权限。

### 状态与可访问性画板

建立 02 States 区域，以独立可编辑组件或局部页面呈现以下状态：

1. 没有待办、没有计划、没有结果记录、搜索无结果。
2. 今日全部处理后，显示完成记录与新增入口，不暗示所有长期目标已完成。
3. 麦克风权限未开启，提供输入文字和系统设置入口。
4. 录音中断后保留已捕获内容，可继续或改文字。
5. 离线已保存、待同步2项、同步成功；不出现永远转动且无解释的加载。
6. 两端改了同一字段的冲突：显示两个候选及日期，用户选择保留哪一个。
7. AI 全部失败、部分成功、待归类、重复事项匹配、撤销成功。
8. 撤销存在后续编辑冲突：展示可撤销范围，不覆盖后来修改。
9. 重复行动本次跳过、整个计划暂停、恢复后从当前日期继续。
10. 数值或单位缺失、记录已更正、没有测量的日期。
11. 批量调整日期或取消事项的影响预览与明确确认。
12. 编辑长标题、系统大字号、键盘展开、长列表滚动、状态不只靠颜色表达。

添加 M01-Dark：使用一致的语义颜色做一张深色今日页。补充 M01-LargeText 与 D02-Narrow 来检查大字和较窄桌面窗口，内容可滚动、面板可收起，不直接缩小所有文字。优先保证所有内容仍然可操作。

如果当前工具支持真实跳转并且已经配置，连接关键流程；否则在画板外提供入口、动作和目标画板标注。不能把未实现的语音、同步、AI、手势或动画称为已完成的交互。

## 最终检查提示词

请对当前 Daily & Beyond 设计文件进行一次完整检查，并直接修复发现的问题。

先确认设计对象是面向普通个人用户的 Apple 双端待办与长期目标应用，界面覆盖工作、学习、健康、生活。确认已有页面中的颜色、字体、导航、组件和同名任务数据一致。

逐张查看实际画布：排除文字溢出、裁切、重叠、按钮遮挡、安全区冲突、对齐错误、对比度不足和不自然换行；不要仅通过图层参数断言视觉正确。桌面不是手机放大版，手机也没有塞入三栏工作台。

检查以下功能表达：

- 单条待办可独立存在，长期计划可没有阶段或结束日期。
- 一次性任务、重复行动、工作或生活记录、数值结果没有混淆。
- 季度汇报完成数3/7，旧快照2/7；阶段、分组与取消项不重复计数。
- 健康行动0/3与体重68.7公斤分开显示，不产生减重达标率或健康因果结论。
- AI 已明确完成的操作有撤销，不要求重复确认；不确定或重要变更才确认。
- 同一任务的开始时间与结束时间不混淆；语音匹配已有任务不重复新建。
- 树、时间线与历史快照表达不同信息，查看旧快照有日期和只读提示。
- iPhone 可以独立建立与编辑计划、改频率、补记结果、暂停恢复和查历史。
- 受限健康内容没有出现在未经允许的云 AI 建议里。
- 所有状态都是可编辑设计元素，组件可以复用。
