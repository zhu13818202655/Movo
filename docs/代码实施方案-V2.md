# Movo 代码实施方案

依据：`Movo-PRD.md` v1.1（下称 PRD）、`Movo-UI-Prompt.md`、`Movo.pen`（页面全集 D01–D10、M01–M14、D09-Snapshot、D05-BulkPreview、M04 系列、M09 系列、M11 系列、M13 系列及 02 States），以及已确定的"用户自行输入模型服务 API Key（内置厂商 + 自定义 OpenAI 兼容厂商），密钥仅保存在当前设备"方案。

本方案细化到字段、签名、算法、步骤与退出条件，开发可直接按第 11 章的步骤开工。除第 14 章明确标注"开工时固定"的参数外，本方案不含开放决策。

## 2026-09-30 待办与多级任务调整

本次调整替代原版“今日作为一级入口、仅一层子任务、首页输入先进入 Capture”的约定。手动创建使用 `CreateTask`；详细创建与移动分别由 `NewTaskSheet`、`MoveTaskSheet` 承载。`TodoFilter` / `TodoNode` / `todos()` 提供过滤后的任务树，`TaskOutline` 负责折叠、子任务添加、移动、提升与删除确认。Mac 支持菜单缩进；手机使用上级标题及任务详情导航。

`TaskHierarchy` 统一遍历，`ReassignTask` 移动全部后代并处理跨计划依赖；`DeleteTask` 预览后写整棵树的墓碑；恢复只匹配同一删除操作。每次手动操作保留批次用于撤销，撤销检查所有受影响实体及后续新增后代。父任务完成态由后代叶子派生，重复模板暂不参与嵌套。

复用现有 `parentId`，不新增持久化字段；操作枚举新增 `deleteTask`，开启跨设备同步前应一起更新客户端，旧客户端未知枚举值的导入需另行验证。内部 `.today` 和 `/today` 兼容保留。新增 `TodoHierarchyTests` 覆盖层级、过滤、移动撤销、删除恢复及可选字段清除；Apple 平台构建与测试需在 macOS 执行。

## 1. 技术决策（已定）

| 项目 | 决策 |
| --- | --- |
| 客户端 | Swift 6、SwiftUI，单一 Xcode 多平台项目；macOS 与 iOS 各自组织导航与交互，共用领域层、设计令牌与大部分功能视图。 |
| 首版系统目标 | iOS 26.0+、macOS 26.0+（统一使用新 Speech API）。如需支持旧系统，另加兼容适配器，不改领域模型。 |
| 并发 | Swift 6 严格并发检查，warnings-as-errors；跨 actor 数据一律走 `Sendable` 值类型；UI 状态在 `@MainActor`。 |
| 本地数据 | SwiftData 保存全部业务数据；`Domain` 层不 import SwiftData，经仓储协议 `DomainRepository` 读写。所有业务对象使用客户端生成的稳定 UUID。 |
| 设备同步 | 首阶段纯本地；P3 接入 CloudKit 私有数据库 + `CKSyncEngine` 自定义合并，业务冲突由领域层裁决。**禁止**同时开启 SwiftData 自动 CloudKit 同步（两套写入路径）。 |
| 用户密钥 | 用户在当前设备自行输入所选厂商的 API Key：内置厂商（目前为 DeepSeek）与自定义厂商（OpenAI 兼容，自填 Base URL 与模型 ID）；Security Keychain 设备专属（`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`）、不启用 iCloud Keychain 同步；不得写入 SwiftData、CloudKit、日志、导出文件、剪贴板外的任何存储。Base URL 与模型 ID 非凭据，存本机偏好。Mac 与 iPhone 分别配置。 |
| 大模型 | 客户端经 HTTPS 直连用户选定的模型服务，协议统一为 OpenAI 兼容（Chat Completions + `json_object`）：`AIProvider` 统一业务协议，`OpenAICompatibleAdapter` 负责请求格式与结构化输出，端点由 `AIProviderResolver` 解析（内置厂商取 `ModelCatalog`，自定义厂商取用户配置）。没有 Movo AI 后端，不转发用户内容。 |
| 语音 | Apple Speech 框架本机转写，`SpeechAnalyzer` + `SpeechTranscriber`（iOS/macOS 26）。只有能力检查（可用性、语言、本机资源）通过才允许录音；不自动切云语音。 |
| 提醒和搜索 | 本地通知（`UNUserNotificationCenter`）；本地倒排/分词索引查询。首版无服务器搜索、推送服务或用户账户体系（iCloud 仅用于同步）。 |
| 第三方依赖 | 首版零第三方依赖；全部系统框架。模型、同步、语音、存储均经协议边界可替换。 |

### 1.1 数据边界

任务和计划存在本机，可按计划设置同步到用户的 iCloud 私有数据库。AI Key 永远仅存在当前设备。**是否把内容发给厂商只由全局「AI 开关」决定**：开关打开时输入原文原样发送；关闭时不发任何请求，原文只留在本机。"Key 本地保存"不代表"所有内容都只留在本机"。计划上的 `cloudAIEnabled` 仅记录分类默认值（工作／学习／生活 true、健康 false、未分类兜底 true），**不参与是否发送的判定**；`syncEnabled` 默认开启（可逐计划关闭），只约束同步。

### 1.2 非功能目标（工程口径，来自 PRD 15.2）

| 指标 | 目标 | 测量方式 |
| --- | --- | --- |
| 本地新增反馈 | P95 ≤ 300ms | 命令执行 + 首帧更新，性能测试固定 20 计划/1 万任务/10 万事件数据集 |
| 今日首屏（有缓存） | P95 ≤ 1s | 冷启动→列表可见 |
| 大计划树首屏 | P95 ≤ 1.5s | 按需展开加载 |
| 前台双端同步可见延迟 | P95 ≤ 5s（正常网络） | 同步集成测试计时 |
| 文字解析（≤500 字、≤10 动作） | 输入结束→结构化结果 P95 ≤ 8s | 按网络/模型分组记录 |
| 60s 内录音 | 停止后 15s 内出结构化结果 | 同上 |
| 超时兜底 | 超过 15s 必须显示进度或重试，原文不丢 | 路径验收 |

### 1.3 架构约定

- 页面 → `@Observable` ViewModel → `DomainStore`（actor）或仓储查询；页面**不得**直接修改多个数据库实体。写入模型（定稿）：`DomainStore` 是唯一写串行化门面，事务体固定执行在主 `ModelContext`（`@MainActor`）内；actor 与主上下文之间只传 `Sendable` 值类型，`@Model` 对象不跨边界；事务外的校验与实例化规划为纯计算。
- `Domain/` 不依赖 SwiftUI、CloudKit、厂商 SDK、UIKit/AppKit；只使用 Foundation。
- 写入唯一入口：领域命令（第 4.2 节）；查询只读视图。
- 时间语义：`DateOnly`（日期语义，携带创建时区）与 `DateTimeTZ`（带时刻与 IANA 时区）是两种独立值类型，禁止用裸 `Date` 表达"某天"（见 3.1）。
- 错误：统一 `MovoError`（4.5 节），每个错误带用户可执行的恢复动作提示；UI 不允许出现无恢复入口的错误态。
- 日志：`RedactedLogger` 只输出结构化元数据；禁记清单 = 任务正文、输入原文、测量值、Key、音频、厂商请求/响应正文（见 8.8）。

### 2.3 编码与命名约定

- 类型：领域实体 PascalCase 无后缀（`Plan`、`Task`）；`@Model` 持久类加 `M` 后缀（`PlanM`）；ViewModel 加 `VM` 后缀；协议能力名用名词（`AIProvider`）。

- 所有 ID 为 `UUID` 字符串持久化；对外展示不用 ID 做文案。
- 日期字符串格式固定 `yyyy-MM-dd`；JSON 时间戳用 ISO 8601 带偏移。

## 3. 领域模型（字段定稿）

### 3.1 值类型与枚举

```swift
enum PlanKind: String { case delivery, improvement, maintenance }        // 交付／改善／持续
enum PlanCategory: String { case work, study, health, life }             // 分类（可选）
enum PlanStatus: String { case active, paused, archived }                // 删除用 Tombstone 表达
enum TaskStatus: String { case todo, inProgress, blocked, done, cancelled }
enum TaskPriority: String { case low, normal, high }
enum OccurrenceStatus: String { case pending, done, skipped }
enum RecurrencePattern: String { case daily, weekdays, weeklyCount }     // 每日／固定星期／每周 N 次
enum StageStatus: String { case notStarted, inProgress, awaitingConfirm, achieved, paused, cancelled }
enum SourceKind: String { case manual, text, voice, ai }
enum TimeValue { case precise(Date) ; case day(DateOnly) ; case month(DateOnly) } // 记录时间粒度

/// 日期语义（"周五交报告"）。sourceTZ 为创建时的 IANA 时区，跨时区旅行不改日期。
struct DateOnly: Hashable, Sendable { let y: Int; let m: Int; let d: Int; let sourceTZ: String }
/// 带时刻的安排/截止。
struct DateTimeTZ: Hashable, Sendable { let epoch: Date; let tzID: String }
```

规则：
- "明天""下周"按**输入发生时刻**的设备时区解析为 `DateOnly`，结果必须显示为明确日期（PRD 4.4）。
- 仅日期（`scheduledDate`）与硬截止（`hardDeadline`，`DateTimeTZ`）是两个独立字段，界面必须能看出差异（AC02）。
- 跨时区：`DateOnly.sourceTZ` 保留创建时区，显示时按设备当前时区换算并提示差异（"原定周五"）。

### 3.3 关系与约束

```text
Plan 1—n Stage 1—n Task 1—n Task(多级子任务)
Task(isTemplate) 1—1 RecurrenceRule 1—n RecurrenceOccurrence
Plan 1—n PlanMetric 1—n Measurement
Capture 1—n SourceSpan → 触发 OperationBatch 1—n Operation 1—n ChangeEvent
```

硬约束（保存前校验，违反则拒绝并保留原输入，AC09）：
- C1 子任务必须与父任务同计划、同阶段；C2 一次性任务支持多级嵌套，重复模板不参与嵌套；C3 不允许自引用/环（校验 parentId 链）；
- C4 isTemplate 任务必须存在 RecurrenceRule；C5 Measurement 必须挂在同计划 PlanMetric 下；
- C6 Occurrence 必须引用有效（未删除）规则版本；C7 archived 计划不接收自动归类（明确指定时提示恢复或作为历史补记，PRD 5.3）；
- C8 已 tombstone 对象拒绝一切写入（唯一例外：恢复命令）；
- C9 前置依赖不得自引用、不得成环（DFS 校验 dependencyIDs 链）、不得跨计划；前置被取消/删除（tombstone）时自动视为解除并忽略，不阻断后继。

前置依赖范围（定稿，REQ 09；2026-09-29 更新：依赖图纳入本版实施）：仅支持同计划内、多前置；任务详情高级区提供前置/后继列表与一跳关系图，计划树（高级开关）与今日显示就绪/等待徽标；手动提前执行/完成仅提示关联影响、不阻断（PRD 6.3）；AI 可建议先后顺序，须采纳后写入；不做复杂自动排程（PRD 7.1 后置）。

### 3.4 revision 与事件约定

- 每个实体 `revision` 从 1 起，任何字段变更 +1；`Operation.baseRevision` 必须等于读取时的 revision，否则报版本冲突（UI 刷新后重试）。
- ChangeEvent 只追加、不改写、不删除（随实体永久删除一并清理）；快照、撤销、同步、历史时间线全部从事件重建。
- 补记不改写录入时间：`occurredAt` 用用户指定时间，`recordedAt` 用当前时间。

### 4.3 查询视图

- `TodayView`：分三段——重点（今天到期的截止、今天的 Occurrence、scheduledDate=今天、进行中的任务）、稍后再做（无日期/逾期，逾期项提供"补做/改期/取消"）、已完成（今日完成，含 Occurrence 完成）。同一 taskId 与计划树同源（P0 完成条件）。
- `PlanSummary`：名称、kind 徽章、分类标签、状态、按类型的进度文本：交付型 `3/7`；改善型 `本周 2/3 · 最新 68.7kg`；持续型 `本周 0/3`（分母为 0 不显示百分比）。
- `PlanTreeView`：depth 0 = 阶段+顶层任务；展开返回子任务与**当前周期**实例（历史实例折叠，显示计数，REQ 14）。
- `DependencyState`：就绪 / 等待（未完成前置 n 项；忽略已取消与已删除前置；派生不落库），供今日、树、任务详情共用（4.4 dependencyStatus）。
- `TimelineEntry`：事件+行动记录+实例统一时间线，类型过滤（含"已取消事项"过滤，M11-HistoryFilter）。
- `ReviewView`：事实区（每计划：行动完成 x/y、跳过、未记录、测量值变化、结构变更事件）、数据缺口（"本周无记录"）、来源链接、建议区（可选，带来源文本，REQ 17）。
- `PlanSnapshot`：截至 asOf 的事件重建（当时目标/结构/频率/测量），**只读**（AC14/AC22）。
- `InboxView`：未归类任务、待处理 Capture、校验未过项、同步冲突（分区展示）。

### 4.4 策略算法（Policies，纯函数+单测覆盖）

**progressFor(plan)**

```text
delivery:    leaves = 计划内叶子任务 − cancelled − 模板任务(重复例行不进分母)
             返回 Fraction(done, total)；total==0 → 空进度，不显示百分比
improvement: 返回 { 周期行动: (done, planned, skipped, unrecorded),
                    指标: [ {metric, latest, delta, 缺测标记} ] }  // 不合成总百分比
maintenance: 返回 周期计数（done/planned/skipped/unrecorded），不显示总体 100%
```

**materializeOccurrences(rule, range)**（惰性实例化，查询/今日构建时触发）

```text
window = [ max(rule.effectiveFrom, range.lower), min(rule.effectiveUntil ?? range.upper, range.upper) ]
for d in window 且 patternMatches(rule, d):
    if d 落在计划暂停区间 [pausedAt, resumedAt): continue          // 不补造
    upsert Occurrence(rule, d, .pending)   // 唯一键 (ruleId, ruleVersion, scheduledOn)，幂等
rule.version 变更：新版本只实例化 effectiveFrom 之后的日期；已存在实例保留
"未记录"派生：scheduledOn < 今天 且 status==pending → 显示未记录（不落库）
```

**weeklyProgress(weeklyCount 规则, week)**

```text
done     = occurrences(status=.done, occurredOn ∈ week).count
skipped  = occurrences(status=.skipped, occurredOn ∈ week).count
unrecorded = 周未结束时不计算；周结束后 = max(0, weeklyCount − done − skipped)
展示：done/weeklyCount（+ 已跳过 n；done 超过 weeklyCount 时显示 N/N 并列出多余记录，不丢数据）
```

**undo(batch)**（补偿事件）

```text
for op in batch.operations 逆序:
    if op.kind ∈ 不可撤销集 {DeletePlan, ResolveConflict, RestoreEntity}: 列入"不可撤销"
    else:
        for e in op 影响的实体:
            if e.revision > op.baseRevision: 标记该 op 为"有后续编辑"，列出冲突说明，跳过
        在同一事务中执行反向命令，写 ChangeEvent(undoOf=op.id)，e.revision+1
返回 UndoResult(undone: [...], unsafe: [(op, 原因)])   // UI 展示可撤销范围，不覆盖后续编辑（AC10）
```

反向映射：create\*→删除新建对象（30 天内可经最近删除找回）；complete\*→reopen；schedule/deadline/update→恢复 patch.old；skip→回 pending；log/measurement→标记删除（保留事件链）；ChangeRecurrence→回退旧规则版本。

**dependencyStatus(task, planTasks)**（纯函数，派生不落库）

```text
blockedBy = dependencyIDs 中 status ∉ {done, cancelled, tombstone} 的数量
ready     = blockedBy == 0
展示：任务行「等待 n / 就绪」徽标；完成或取消前置后即时更新；不阻断任何操作（PRD 6.3“仅提示”）
```

**隐私总闸（全局 AI 开关，详见 6.3）** 与 **fieldMerge（事件式三方合并，详见 9.4）** 是隐私与同步的核心，单测必须覆盖第 12 章固定用例。

### 4.5 错误模型

```swift
enum MovoError: LocalizedError {
    case invalidStructure(reason)        // C1–C9 约束
    case versionConflict(entityID)       // baseRevision 不匹配 → UI 刷新重试
    case notFound(entityType, id)
    case permissionDenied(kind: PermissionKind)     // mic/speech/notification
    case speechUnavailable(reason: SpeechFailReason) // 权限拒绝/不支持/资源未装
    case noKey(vendor)                   // 无 Key → 手动模式提示
    case providerNotConfigured(vendor)   // 自定义厂商缺 Base URL / 模型 ID → 先去设置页补全
    case aiFailed(stage: AIStage, cause) // 网络/超时/429/401/解析失败
    case aiRejected([RejectReason])      // 校验未过项 → 收件箱
    case syncFailed(reason, retryAt)
    case conflictPending(count)
    case exportUnavailable(reason)
    case cancelled
}
```

每个 case 绑定固定文案与恢复动作（重试/改文字输入/去设置/查看冲突），UI 层用 `ErrorBanner` 统一渲染，禁止裸错误。

三个派生于该模型的约定：

| 成员 | 作用 |
| --- | --- |
| `AIStage` | `auth / rateLimited / timeout / network / parse / invalidRequest / unknown`。`invalidRequest` 对应其余 4xx（端点路径或模型 ID 不对），使这类失败不再渲染成「未知错误」 |
| `AIFailureCause` | `cause` 是机器标识（进 `RedactedLogger` 元数据，不随文案变化）；`explanation(for:)` 把它翻成用户可执行的解释 |
| `diagnosticDetail` / `isConfigurationGap` | 前者给设置页「测试连接」用（无「原文已经保存」语境）；后者标记 `noKey` 与 `providerNotConfigured`，供输入管线区分「缺配置」与「整理失败」 |

`isRetryable` 在 8.6 的「仅网络/429/5xx」之上再排除确定性失败（明文 HTTP 被 ATS 拦下、证书不受信、域名解析失败），避免对着写错的地址反复重试。

### 5.3 搜索索引

`SearchDocM { id, entityType, entityId, planID?, title, body, tokens }`：
- 分词：中文按二元组（bigram）+ 完整词；拉丁/数字按空白与标点切词；统一小写。
- 维护：随实体事务增量 upsert/删除；不单独重建（提供"重建索引"入口，设置页）。
- 查询：`#Predicate` 对 tokens 做包含匹配，多词 AND；结果按 类型>时间 排序；跳原对象（深链）。

### 5.4 Schema 版本与迁移

- 首版 `schemaVersion = 1`，`ModelContainer` 注册全部 @Model + `VersionedSchema` + `SchemaMigrationPlan`。
- 规则：只允许**新增列/新增表**；删列先弃用一个版本；重命名=新列+迁移+旧列弃用。
- 每个迁移必须有 fixture 数据库 round-trip 测试（旧版本库打开→迁移→数据一致）。

## 6. 输入管线（Capture）

### 6.1 总体状态机

```text
idle → drafting(文字) | recording → finalizing → transcriptEditing
     → captured(Capture 落库, state=saved)
     → gateCheck(全局 AI 开关 + 凭据预检：任一不满足即停在 saved，原文保留)
     → contextBuild → aiRunning → validated
     → previewConfirm(全部进入待确认；可逐项取消，父项级联取消后代)
     → applied(部分成功允许) → 结果条(成功/部分/失败) + 撤销入口
失败分支：aiFailed(原文已保存, 可重试/手动) ; speechFailed(保留已捕获文字)
```

> 注：早期稿中的 `privacySplit`（本地拆分/片段标记）与 `localDirect`（本地确定性直执）已移除；是否发送只由全局 AI 开关决定，输入原文原样发送（见 6.3）。

任何一步失败，`Capture.state` 与 `rawText` 已持久化，离开页面再回来可继续（REQ 02）。

### 6.2 管线步骤（C1–C10）

| 步 | 动作 | 持久化 | 失败处理 |
| --- | --- | --- | --- |
| C1 | 采集：文字/粘贴/语音转写（可编辑） | 生成 Capture（saved） | 语音无可靠文字→转文字录入，不提交 AI |
| C2 | 全局 AI 开关与凭据预检：`AISettingsStore.isGlobalAIEnabled`；所选厂商 Key / 自定义端点配置是否齐全 | 不落库，仅更新 `Capture.state` | 开关关闭或未配置→state=saved，原文保留并引导设置，**不发起任何网络请求** |
| C3 | 读取上下文来源：未归档计划、阶段、活跃任务树、指标 id、重复模板（排除 tombstone） | AIInput 输入素材（内存） | 无计划→仍可整理为独立待办 |
| C4 | 构建云上下文（`AIContextBuilder`，见 6.4）：**输入原文原样** + 全部未归档计划及其阶段/任务/重复模板 | AIInput（内存，不落日志） | — |

| C10 | 重试：同 capture 重试生成同 batchId；已 applied 的 operationId 跳过（幂等） | | |

### 6.3 隐私总闸（全局 AI 开关）

隐私决策只有一个开关，只有两个状态：

- **关闭**：不向任何模型服务商发起网络请求。`AISettingsStore.isGlobalAIEnabled == false` 时，App 层与 `ProposalService.prepare` 各有一道闸门，直接返回、把 `Capture.state` 置为 `saved` 并保留原文；本地基础功能（新增/编辑/完成/记录/树浏览）完全可用（REQ 19）。
- **开启**：用户输入**原文原样**发往所选厂商（`request.effectiveText`，未编辑则为 `rawText`）；Key 仅存本机 Keychain，传输日志严格脱敏（8.8）。开启 AI 开关与首次使用 AI 输入时各告知一次「原文会原样发给所配置的模型服务商」（PRD 11.2）。

**已移除的旧机制**（不再作为发送条件，文档中不再保留其算法）：

- 逐句拆分与「受限/敏感/混合」片段判定、内置健康词表匹配；
- 按计划分类默认的 `cloudAIEnabled` 闸门——计划上的 `cloudAIEnabled` 仅作为**分类默认值的记录**随实体同步与展示，**不参与任何发送判定**（见 1.1）；
- 本地确定性直执分流（原 C3）——AI 提议一律经校验后进入预览，由用户确认。

**仍不进请求体的内容**（结构性边界，与开关状态无关）：测量值正文、行动记录正文、事件历史、Key、设备标识；指标只发送 id。计划与任务的名称/标题/别名**会**发送（用于归类），包括健康计划（见 6.4）。

设备/语言能力差异导致「四项全部自动整理」可能只是部分成立，这是成功态示例而非每台设备必达承诺。

  "items": [
    {
      "source_span": "明天把季度汇报的数据补齐",

      "task": {

        "notes": null,
        "plan_id": "plan-uuid",

        "parent_task_id": null,

        "dependency_ids": []
      },

- `action` 枚举（定稿）：`create_task`、`update_task`（带 candidate_task_id + 字段 patch）、`schedule_existing_task`、`complete_task`、`match_occurrence`、`log_activity`、`record_measurement`、`set_recurrence`、`set_dependency`（先后顺序建议）、`save_note`、`needs_clarification`。"查询"类意图不走云：本地路由到搜索。

- 依赖建议（`create_task.dependency_ids`、`set_dependency`）一律 `needs_confirmation=true`，经采纳后写入；引用必须来自本次上下文且同计划（V13，REQ 09）。
- `confidence` 仅内部使用（阈值判定），界面不展示数值，展示 `reason` 文案。
- 除 task/recurrence/measurement/note 中与 action 对应的块外，其余必须为 null；单条输入 ≤10 个 items（PRD 15.2 口径）。

## 7. 语音转写（本机）

### 7.1 能力与权限流程（开始录音前，固定顺序）

1. 麦克风权限：未定→请求（说明用途）；拒绝→转文字录入 + 系统设置入口（M01-Dark 状态 3 / 02 States B）。
2. `SpeechTranscriber.isAvailable` 与 `supportedLocales` 含目标语言（首版 zh-Hans 为主，en 混合）。
3. 本机能力确认：目标语言是否支持 on-device（不满足→只允许用户**主动选择**后继续？定稿：不满足 on-device 则不开放录音，转文字；不暗中上传，PRD 4.4/11.2）。
4. 语言模型资源：`SpeechAssetInventory` 检查；未安装→展示下载进度（`ensureResources`），用户确认后安装，安装完再录音。
5. 全部通过→进入录音。能力检查结果缓存于会话内，权限/资源状态变化时重查。

### 7.2 服务接口

```swift
struct SpeechCapability: Sendable {
    var mic: PermissionState
    var supported: Bool
    var onDevice: Bool
    var resources: ResourceState          // notInstalled / downloadable(Progress) / installed
}
protocol SpeechTranscriptionService: Sendable {
    func capability(locale: Locale) async -> SpeechCapability
    func ensureResources(locale: Locale) async throws -> Progress
    func makeSession(locale: Locale) -> SpeechSession
}
struct SpeechSession {
    func start() async throws
    var updates: AsyncStream<TranscriptUpdate>   // { finals: [String], partial: String? }
    func stop() async -> TranscriptFinal         // 等待最后片段（≤3s 超时兜底）
    func cancel()
}
```

实时字幕维护规则：finals 只追加；partial 单独渲染在末尾；final 到达时移除对应 partial 前缀，避免重复（6.1 状态机要求）。

### 7.3 录音状态机与中断

```text
idle → checking → ready → recording → finalizing → transcriptEditing → saved/failed
recording ⇄ pausedInterrupted（来电/系统音频中断：AVAudioSession interruption）
```

- 中断：暂停录音，**保留已捕获文字**；恢复后提供"继续录音/停止并整理/转文字"（AC03）。
- 单段上限 3 分钟：到点自动 finalizing，允许"续录"（同 Capture 追加新段，UI 拼接）（REQ 03）。
- `stop()` 后等待最后 final 片段（3s 超时兜底，超时用已得 finals）。
- 失败分支：无可靠文字→不提交 AI；提供"重试/改文字"。转写失败的原始音频：询问用户是否保留，`retain24h` 默认 24h 到期自动删除，仅本机、不进同步/日志/导出（REQ 03、PRD 11.2）。
- 语音识别（本机）与语义理解（云 AI）是两个组件：转写成功但无 Key/离线时，原文照常保存，AI 整理可稍后重试。

### 7.4 UI 映射

`M04-Recording`（波形+实时字幕+隐私提示"转写在本机完成"）、`M04-Transcript`（可编辑，强调人名/数字/专有名词纠错）、`M04-Processing`（进度：整理中→可重试）、`M04-Failed`（原文已保留）。全局 AI 开关关闭时统一提示"原文已保存、可在设置中开启 AI"，不再有按计划区分的本地录入分支。

## 8. 大模型调用（BYOK）

### 8.1 KeyStore（Keychain）

```swift
protocol AIKeyStore: Sendable {
    func key(vendor: AIVendor) -> String?
    func save(_ key: String, vendor: AIVendor) throws
    func delete(vendor: AIVendor) throws

```

- `kSecClassGenericPassword`；service = `Movo.AIKey.deepseek` / `Movo.AIKey.custom`；account = `default`；
- accessibility = `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`；**不启用** iCloud Keychain 同步；
- 设置页（M13 AI 区）：选厂商→输入 Key（输入框粘贴后本地校验格式）→立即"测试连接"→保存；显示掩码（`sk-…abcd` 末 4 位）、最近调用错误（不显示 Key）、替换/删除；
- Key 只进 Keychain；日志、导出、崩溃报告均不可出现（PT 测试扫描：SwiftData dump、CK 记录、导出文件、日志文件、crash log）。
- 设备语义（定稿）：Key 永不离开设备——不随备份、iCloud 钥匙串或换机迁移（`ThisDeviceOnly`）；同设备重装后若 Keychain 条目仍在则继续可用，设置页提供显式"删除 Key"（不依赖卸载清除）。

### 8.2 AIProvider 协议

```swift
struct AIInput: Sendable { /* 6.4 的 JSON 结构 */ }
struct AIProposal: Sendable { /* 6.5 的 JSON 结构，含 provider/model 元数据 */ }
struct ModelInfo: Sendable { let id: String; let displayName: String; let contextHint: String? }
protocol AIProvider: Sendable {
    var id: AIVendor { get }
    func availableModels() -> [ModelInfo]                       // 内置厂商来自 ModelsCatalog.json；自定义厂商为单一自填模型
    func testConnection() async throws                          // 最小请求验证 Base URL + Key + 模型
    func proposeOperations(_ input: AIInput) async throws -> AIProposal
}
```

`Intelligence/Planning/ProposalService` 统一编排：选 provider → 组装输入 → 调用 → 解析 → 6.6 校验 → 6.7 策略。

### 8.3 OpenAICompatibleAdapter（OpenAI 兼容）

内置厂商与自定义厂商共用同一协议实现，端点由 `AIProviderResolver` 提供：

- 端点：内置 DeepSeek 为 `https://api.deepseek.com/v1/chat/completions`；自定义厂商为 `<Base URL>/chat/completions`（用户填到 `/v1` 即可）。header `Authorization: Bearer <key>`。
- 请求：`messages=[system(固定指令 6.4 instructions), user(上下文 JSON)]`；`response_format = { type: "json_object" }`（6.5 的 JSON Schema 以指令内嵌，客户端严格解析）。
- 响应：解析 `choices[0].message.content` → AIProposal；同时记录 usage（prompt/completion tokens）。
- 错误映射：401/403→`aiFailed(.auth)`（提示检查 Key，不重试）；429/5xx→指数退避重试 1s→2s（最多 2 次）后 `aiFailed(.rateLimited)`；超时→`aiFailed(.timeout)`；其余 4xx→`aiFailed(.invalidRequest, "http_<状态码>")`（端点或模型 ID 不对，不重试）；解析失败→`aiFailed(.parse)`（原文保留，可重试）；`URLError` 归一为 `AIFailureCause` 中的语义 cause（`ats_plain_http` / `tls_trust` / `dns` / `connect_refused` / `offline` / `connection_lost`），未知码保留 `urlerror_<码>`。
- 「测试连接」发一条最小 chat 请求（`max_tokens: 1`，不带 `response_format`），一次性验证 Base URL、Key 与模型 ID；不依赖 `GET /models`，自建服务也可用。

### 8.4 厂商解析与自定义配置

- `AIVendor`：`deepseek`（内置）与 `custom`（自定义），新增内置厂商时加 case 并在 `ModelCatalog` 登记。
- `AIProviderResolver.resolve`：把厂商 + 选择解析为 `{ displayName, model, models, chatCompletionsURL }`；自定义厂商缺 Base URL 或模型 ID 时抛 `MovoError.providerNotConfigured`。
- `CustomProviderConfig`：`baseURL` + `modelID`，归一化去空白与尾斜杠、支持用户直接粘完整端点；`isComplete` 判定两项是否都填好。
- `AISettingsStore`：厂商选择与自定义配置整体持久化到本机偏好（Key 仍只进 Keychain）；解码失败回落默认值。
- 未就绪时的降级：`AIProviderResolver` 抛错 → `processCapture` 走本地整理并把错误写进 `lastError`，原文不丢。
- 缺配置不是整理失败：`MovoError.isConfigurationGap` 标记 `noKey` 与 `providerNotConfigured`，输入管线据此进去结果页（M02）并给出「去设置页补全」恢复入口，而不是渲染成 M04-Failed「整理没能完成」。

### 8.5 模型清单

`Config/ModelsCatalog.json`：登记**内置厂商**的 chat completions 端点与若干默认模型（id + 显示名 + 上下文提示），整体可更新。自定义厂商（OpenAI 兼容）不登记在此，其 Base URL 与模型 ID 由用户在设置页填写。模型 ID 不写入领域逻辑；每次调用把 `provider+model` 记入调用元数据（PRD 10.3 版本化记录，便于回归与成本分析）。

### 8.6 超时/重试/取消

- 超时：连接 10s、总 30s；用户在整理中页可随时取消（`Task` 取消传播到 URLSession）。
- 重试：仅网络错误/429/5xx 自动重试（8.3/8.4）；4xx 鉴权与解析失败不自动重试；确定性失败（明文 HTTP 被 ATS 拦下、证书不受信、域名解析失败）不自动重试；超过 15s 必须显示进度（1.2 指标）。
- 所有调用可被"整理中"页的取消按钮中断；中断后 Capture.state 回 saved，可重试。

### 8.7 用量与成本

每次调用记录 `{ provider, model, promptTokens, completionTokens, latencyMs, status, date }`；设置页显示近 30 天合计与按厂商/模型分组；用户按厂商 API 实际用量自行付费，界面在首次发送前显示"将发送哪些文字"预览（PRD 11.2）。

### 8.8 日志脱敏

`RedactedLogger` 对 AI 链路只输出：`{ provider, model, status, latencyMs, tokens, itemCount, rejectedCount }`；禁止输出请求/响应正文、Key、设备 ID。全局日志过滤器对任务标题、Capture 原文、测量值做扫描告警（CI 中跑样例文本）。

### 8.9 自定义端点的可达性（ATS）

自定义厂商（8.4）由用户填 Base URL，指向的常是自建服务（Ollama / vLLM / LM Studio 等），也可能是公网 IP 上的明文 HTTP 服务，例如 `http://203.0.113.10:21003/v1`、`http://192.168.x.x:8000/v1`。地址由用户决定，应用**无法按域名逐个放行**。系统自 **iOS 17 / macOS 14 起默认拒绝连接裸 IP**（公网与局域网皆然），且一贯拒绝明文 HTTP；只靠 8.3 的错误映射无法让这类端点变得可用。

`Movo/project.yml` 的 `info:` 段因此声明：

| 键 | 作用 |
| --- | --- |
| `NSAppTransportSecurity.NSAllowsArbitraryLoads` | 取消 ATS 的**协议限制**，明文 HTTP 与裸 IP 均可连接；不改动 URLSession 的默认服务器信任评估，HTTPS 连接仍按原样校验 |
| `NSLocalNetworkUsageDescription` | 局域网地址所需的本地网络访问权限（iOS 14+ / macOS 15+），独立于 ATS，公网 IP 不触发 |

边界与不变式：

- ⚠️ **`NSAllowsArbitraryLoads` 不能与 `NSAllowsLocalNetworking` / `NSAllowsArbitraryLoadsInWebContent` / `NSAllowsArbitraryLoadsForMedia` 共存**：iOS 10+ / macOS 10.12+ 只要见到其中任一个，就忽略 `NSAllowsArbitraryLoads` 并改用默认值 NO。同时设置等于静默失效。
- `NSAppTransportSecurity` 是嵌套字典，无法用 `INFOPLIST_KEY_*` 表达，故额外声明一个由 `info:` 段生成的 `Movo/Info.plist`（不入库）。Xcode 会把全部 `INFOPLIST_KEY_*` 合并进该文件；构建产物已验证同时含 ATS 键与 `NSPrincipalClass`、`UIApplicationSceneManifest` 等既有键。
- **自签名 HTTPS 证书**不被默认信任评估接受；能放行它的 `NSExceptionAllowsInsecureHTTPLoads` 按域名生效，用户自填地址无法事先枚举，故自签名场景需要用户改用受信任证书。
- 该改动放宽的是协议层，不放松隐私边界：是否发送内容仍由 6.3 的**全局 AI 开关**与 AC16 决定。
- 已知代价：公网明文 HTTP 下 `Authorization: Bearer` 与整理内容可能被路径上第三方读取（见 8.8 的脱敏约定与此处的取舍）。上架 App Store 需为 `NSAllowsArbitraryLoads` 提供审核理由。

## 9. 跨设备同步（P3）

### 9.1 原则（定稿）

- 跨设备同步与云 AI 是两条独立链路：同步走 CloudKit 私有数据库，AI Key **永不上传**；按计划 `syncEnabled` 决定是否同步该计划内容。
- 离线操作立即写本机，网络恢复后增量同步；不用设备时间戳"最后写入覆盖"。
- 幂等键：客户端生成的实体 UUID + operationId + eventID；重复事件去重。
- 首版不使用 SwiftData 自动 CloudKit（避免两套写入路径）。

### 9.2 CloudKit 记录 Schema（私有数据库，默认 zone）

| RecordType | 用途 | 字段 |
| --- | --- | --- |
| `MovoEntity` | 每个业务实体一条（Plan/Stage/Task/Rule/Occurrence/Activity/Measurement/Note/Capture/Suggestion/ReviewNote/Tombstone） | `entityType`(String), `entityID`(String, 主键=recordID), `rev`(Int), `deviceId`(String), `updatedAt`(Date), `deletedAt`(Date?, 空=未删), `stateJSON`(Data, 实体全量 JSON), `fieldRev`(Data, {field: revAtLastChange}), `planID`(String?, 根计划，供按计划过滤), `schemaV`(Int) |
| `MovoEvent` | ChangeEvent 追加同步（幂等去重） | `eventID`(recordID), `payloadJSON`(Data), `entityID`, `occurredAt`, `recordedAt` |
| `MovoMeta` | 元数据 | `schemaVersion`, `lastMigratedAt`, `deviceID` |

- 记录大小：stateJSON 控制 ≤64KB（正文超长的 Capture 分段存；超限拆分 `stateJSON_1..n`，映射层透明处理）。
- 事件量大时按 500 条/批推送；拉取用 `CKSyncEngine.fetchChanges` 游标分页。

### 9.3 同步引擎

```swift
actor SyncEngine {
    // 封装 CKSyncEngine（iOS/macOS 26 API）+ 本地 dirty 队列
    func start()                    // 应用启动/登录成功
    func trigger()                  // 触发点：进前台、网络变化、dirty 非空(3s 防抖)、手动"立即同步"
    var state: SyncState            // notSignedIn / idle / syncing(pendingCount) / upToDate / failed(reason, retryAt) / conflictPending(n)
}
```

循环：
1. **出站**：dirty 实体 → 取远端当前记录 → 按 9.4 合并 → 写本地 + `modify` 推送；pending 事件批量 `modify`（远端已存在 eventID 跳过）。
2. **入站**：`fetchChanges` → 对每条远端记录按 9.4 以本地为基准合并 → 写本地 + 发变更流（UI 刷新）+ 更新搜索索引。
3. 冲突：生成/更新 `SyncConflict` 记录并推送（冲突本身也是实体），UI 显示待处理数。

### 9.4 事件式三方合并算法（fieldMerge）

前提：两端共享"上次共同同步点"的历史（即共享状态 S_base）；本地未同步变更 = 本地 `synced=false` 的 ChangeEvent 集 E_l；远端新变更 = 远端事件中 `rev > 本地已知 rev` 的集 E_r。

```text
对每个 (entityType, entityID):
  1. 删除判定：任一侧存在删除事件（deletedAt）且对侧无更新的非删除事件 → 实体删除（tombstone）
     旧设备后补的编辑：删除胜出；编辑被丢弃，若来自 AI 批次则本地提示"该变更未同步（对象已删除）"（AC11）
  2. 应用事件：把 E_l、E_r 中非冲突事件按 rev 序应用到 S_base 的 stateJSON
     同字段被 E_l、E_r 各改一次：
        值相同 → 无冲突，取该值
        值不同 → 生成 SyncConflict(field, localValue, remoteValue, baseRev)，
                 其余字段照常合并，实体状态=合并结果+该字段挂起冲突
  3. 决议：用户选择 local/remote/custom → 写决议事件（新 rev），清除冲突，两端再同步
  4. 幂等：所有步骤以 eventID/operationID 去重；重复推送无副作用
  5. 完成后：本地应用的事件置 synced=true，更新 lastSyncedCursor
```

- 不同字段并行修改自动合并（PRD REQ 20）；同一字段并发修改保留两份候选并提示（不丢失任一版本，P3 完成条件）。
- 冲突 UI（02 States B 第 6 条）：显示两个候选值 + 各自时间与设备（"Mac/ iPhone"），选择后写决议。

### 9.5 Tombstone 与恢复

- 删除 = 写删除事件 + Tombstone（purgeAfter=+30 天）；30 天内"最近删除"可完整恢复（含后代，M13-Recovery）。
- 恢复不补造历史行动；到期永久删除时级联清理事件、索引、CK 记录（AC17）。
- 旧设备离线期对已删对象的编辑不能复活对象（9.4 第 1 步）。

### 9.6 计划同步开关与账号状态

- `syncEnabled=false`：该计划**后续变更**不再出站、不再入站该计划更新；CK 中历史数据保留；重新打开→全量重推该计划实体+pending 事件（可预测行为，设置页文案说明）。
- Capture/Note 无计划归属时跟随账号默认（同步）；有归属跟随该计划开关。
- `cloudAIEnabled` 只是计划上「分类默认值」的记录，随实体同步与展示，**不参与是否发送、也不参与同步出站/入站的判定**；Key 永远不是任何字段。
- iCloud 账号状态机：`notSignedIn → requesting → signedIn → signingOut → notSignedIn`。登录成功→首次全量拉取+推送；**退出前**若存在 pending 数据：提示"等待同步完成"或"导出后退出"（REQ 20）；换机/重装登录同账号→数据回到本机（不依赖单设备密钥或状态）。

### 9.7 永不同步清单

AI Key、原始音频（含 24h 保留件）、诊断日志、本地通知配置、演示数据标记、冲突裁决前的敏感片段（敏感片段本就不出本机）。PT 测试：抓取全部 CK 出站记录做 Key/敏感词扫描。

- 排期：有时刻任务→该时刻；仅日期任务→当天 09:00（Defaults.json 可改）；硬截止→前 1 天 + 当天 09:00（未完成时）；周期回顾提醒（用户选定的回顾时刻）；受阻复查提醒（计划受阻或多次改期时提示，按用户开关，仅基于可观察事实）。
- 聚合与克制：相近提醒聚合发送；支持安静时段；完成/跳过不主动通知；不使用连续打卡类催促文案。
- 内容：标题+计划标签；**不显示健康详情**（PRD 9.4）；点按深链到对象。
- 标识与跨端：通知标识确定性生成（`task-<id>-<date>`），重复排期幂等；任一端完成/跳过 → 对端在下次同步后取消待发提醒；离线窗口不保证绝对无重复（已知限制，设置页注明）。
- 双端可分别设置；权限按需请求。

### 10.10 适配与状态（02 States A–F + 专板）

- 深色（M01-Dark）：语义色映射（背景/表面/正文/主色各深色值在 T0.3 定稿）。
- 大字号（M01-LargeText/Completed）：内容可滚动、不整体缩小；行内控件换行规则。
- Mac 窄窗（D02-Narrow）：详情面板可收起、侧栏折叠、内容滚动。
- 键盘安全区：输入浮层不遮挡底部标签（iPhone）。
- VoiceOver：关键操作有标签与语义（完成开关、候选选择、冲突双候选）；状态不只靠颜色（02 States F）。
- 错误/离线/同步/语音/AI 失败态全部有恢复入口。

### 12.4 隐私专项（PT 清单）

1. F1 混合句：开启全局 AI 时原文原样进入请求体（无按片段裁剪）；关闭时不产生任何网络请求；
2. 请求体中：测量值正文、行动记录正文、事件历史、Key、设备标识 0 出现（计划/任务通道只含 id、名称/标题、别名、状态、时间）；
3. 回顾建议为本地生成，不触发云调用；全局开关关闭后所有入口 0 请求；
4. Key 扫描：SwiftData dump、CK 出站记录、导出文件、日志、crash log；
5. 无 Key/断网时手动操作全可用；
6. 发送预览（8.7）与实际请求体一致；
7. Key 迁移语义：换机/备份恢复后 Keychain 无 Key；同设备重装行为与设置页的删除 Key 入口一致（8.1）。

### 12.5 语音真机矩阵（VT）

设备：iPhone（≥1 台 iOS 26）+ Mac（≥1 台 macOS 26）；语言：中文、英文、中英混说；分支：权限拒绝、模型资源未安装（含下载进度）、来电/音频中断、停止时最后片段、3 分钟上限续录、转写失败保留音频 24h 删除、重启后原文可找回、全局 AI 关闭时提示"原文已保存"。

### 12.6 性能与发布阻断

- 1.2 指标在 F4 上测量（本地反馈/首屏/树/解析延迟），按网络与模型分组记录；
- 阻断项（PRD 15.2）：可复现数据丢失、跨账号泄漏、关闭全局 AI 后仍外发、无指令完成叶子任务、撤销覆盖后续编辑、快照被污染——任一命中即阻塞发布。
